# 工程 Agent：聊天入口、数据空间与统一模块结果

本目录包含**可运行的单窗口接入原型、独立基础库、AI 后台副本、数据空间托管与任务回执**，以及目标架构和契约。当前只能生成诊断草稿，**完整产品数据包和现有计算输入 JSON 尚未实现**。没有改动原五个 AI 模块、原业务模块或原业务数据库。

2026-11-13 根据用户两轮答复确定：

- 独立平台、聊天式入口；原模块功能合并为统一结果与操作面板，连接平台独立数据副本。
- 输入文件一次提交，由主控 Agent 分解任务、分发产品文件及知识上下文，各模块子 Agent 协同完成。
- 复用已有工程数据空间，以数据编织作为统一数据访问、语义关联、版本及追溯层。
- 最终输出计算前的完整结构化产品包，以及现有计算程序需要的输入 JSON。
- 基础数据库先复制后独立使用，运行期间脱离原业务数据库。
- 尽量自动执行；只有缺失必需信息、存在无法消解的冲突或不能继续时，在同一界面集中询问。

最新确认：处理输入中识别出的全部产品，按每台产品的真实类型、型式加载上下文，不固定BKU或首台。复制 `HE3DTB.dll` 作为平台后台几何引擎；允许按预定义配置、规范和确定规则形成有依据的预设计值，后续计算校核；采用库内“默认”配置，由本次文件和规范覆盖明确要求。本期不执行强度计算，不生成计算报告、二维图、三维模型。

缺项先留空并进入Agent loop，执行产品来源复查、适用默认值与字段规则校验；非必需项暂缓，必需性尚未由下游契约确认的项保留 `required=null` 待复核。只有明确必需且仍缺失、冲突或非法的参数进入人工审核。人工填写后重新校验，未填项保留，不停止其它产品。模块能力缺口单独列出，不作为用户缺参数处理。

## 运行

Windows 新电脑双击本目录的 `start.bat`，也可运行 `start.ps1`。启动器会查找现有 Python/Anaconda 环境（包括 `D:\ProgramData\anaconda3\python.exe`）；首次启动自动准备自带数据库，进度直接显示在对话界面，不需要安装 MySQL 服务、填写源库配置或手动运行初始化命令。后续启动复用本机数据。

运行包自带数据库，但仍使用现有 Python 环境；若尚未安装 Python 依赖，在本目录用该环境执行 `python -m pip install -r requirements.txt`。也可直接启动：

```powershell
& 'D:\python3.9\python.exe' 'E:\DongLanpec\AI-part\master_agent_platform\run.py'
```

2026-11-15 界面要求修正：取消“原模块工作台”的产品入口。主界面采用聊天消息、任务历史与底部输入框；模块结果和运行记录是对话内可展开、折叠的结果卡片，侧栏同名入口只跳转到对应卡片，编辑与执行图均不离开对话。数据空间和待审核仍可独立查看。加入输入和知识资料后发送任务，自动逐台处理全部已识别产品。只有明确必需且仍不能解决的字段进入“待审核”；其余缺项继续暂缓，不停止其它产品。

“模块结果”按产品统一展示项目定义、条件数据、元件与材料、管口数据、管束设计。使用共同的表格、依据查看、补充资料、JSON草稿导出、校验、草稿保存和确认保存控件。管束的原几何画布、孔位编辑、撤销与参数联动保留在管板型式、布管、管-板连接、轴向设计四个标签页中；编辑时“模块结果”卡片接管聊天页的整块工作区（对话流、快捷入口与提示行自动收起，卡片右上角“展开对话”可随时放回），因此 1100×700 左右的布管页面不需要拖动滚动条即可看全；操作与保存回执仍返回平台，不另开最大化窗口。现有解析、材料校验/部分合法写入和几何服务在后台复用，用户不再打开原应用侧栏和聊天窗口。

聊天中可以按产品路由模块指令，例如“OST-E-1901 壳程设计压力改为 3.2 MPa”“把 1 的外伸高度改成 180”。模块操作回执返回对话，确认后点“保存并继续审核”。保存草稿只存证，不采用未确认值。项目清单可跨已识别产品编辑名称等字段；新增/删除及类型型式变更仍保留为提案，需重新识别和模板适配后采用，不静默删除已处理数据。无几何适配的型式保持待适配，不替换为其它型式。

“数据空间”显式展示托管文件版本与SHA256、输入到产品分片的原文页关联、知识片段和实际检索分发、资源目录，以及结构化字段来源和适用的基础模板/默认配置。产品审核JSON快照自动登记到既有数据中心资源库并按版本托管。普通用户不需要配置数据库连接。

“运行记录”初始按任务、产品、模块、真实调用分层成树，产品导航可筛选，分组可双击展开或折叠。每个节点均可拖动，文字与连线跟随；布局保存在 `workspace/graph_layouts/<run_id>.json`，刷新、筛选和重新打开任务后保留，可点“恢复树形”重置。蓝线表示归属，勾选“显示调用依赖”查看实际先后关系，紫线表示已发生的审核返回；不会因同一模块被多次打开就虚构循环。

审核循环来自产品已有 `review.rounds` 与新增 `review.cycles` 回执。新轮次记录触发原因、阶段和总耗时、采纳数及暂缓/送审数量；历史轮次只展示已有步骤，不补造计时。当前仍是来源复查、适用默认值与字段校验的有界复核，保存或补充后再次执行，尚未实现通用大模型自主重规划。实际任务节点保留调用状态、开始/结束、知识检索量、输入、摘要和回执路径；图的树形归属不代表调度器已经并行执行。

已有任务可从“最近任务”或“载入任务结果”打开，也可传 `--result <summary.json>`。聊天记录保存在 `workspace/conversations`，模块工作副本与操作回执保存在 `workspace/evidence_sessions`。`ui_vendor` 用于后台复用现有功能部件，`evidence_runtime.py` 原窗口方案保留为历史验证工具，当前入口使用 `module_runtime.py` 的统一编辑器。当前聊天提供工程任务、模块指令和导航路由；未宣称接入通用大模型自由对话或验证在线模型服务。

“新建对话”会保留当前聊天和模块工作副本，待保存回执处理完毕、编辑器关闭后自动切换，清空旧任务的模块、审核、数据空间和执行图视图。未确认编辑仅保留为草稿；历史任务仍可恢复。任务运行中点击时会显示等待状态，任务结束或停止后自动开启新对话。

当前Agent loop为有界的来源复查、适用模板及确定规则审核，并非已经完成自然语言动态重规划。完整元件预设计与正式计算JSON导出仍未接入，暂缓不代表工程完整性通过。

命令行同样处理全部识别产品，不再使用 `--tag`：

```powershell
& 'D:\python3.9\python.exe' 'E:\DongLanpec\AI-part\master_agent_platform\run_pipeline.py' '<输入PDF>'
& 'D:\python3.9\python.exe' 'E:\DongLanpec\AI-part\master_agent_platform\run_pipeline.py' --recheck-run '<任务ID>'
```

平台自带 `bundled_database/mysql` 下的 MySQL 8.0.43 Windows x64 运行时，以及经过校验的基础数据种子：148 张表、47,151 条记录，包含材料、元件、产品定义、条件模板及“默认”配置；项目、产品和活动库仅提供空表结构。不会携带历史产品、任务、其它项目配置或本机密码。程序自动生成 `workspace/mysql/data`、随机本机密码、连接配置和校验回执；优先使用端口13316，占用时自动选择其它独立端口，监听本机127.0.0.1，不连接原3306业务库。

中文、空格或较长路径通过本机应用数据目录中的兼容路径映射启动 MySQL，数据库实体仍位于本平台 workspace。已初始化的独立数据库目录迁移后会核对所有权并更新连接路径；这不等于历史任务内所有原文绝对路径都已迁移。更新代码不覆盖已有基础库和产品数据。跨机接续历史任务仍需另行迁移数据空间和文件引用。

Git 和运行包包含源码、后台副本、自带数据库引擎与默认基础数据；不包含 `workspace` 中的运行数据库、输入文件、任务记录和本地密钥。可选的管口在线模型配置参见 `vendor/nozzle_agent/config.example.json`，按需复制为同目录下已忽略的 `config.json`；未配置时使用本地规则引擎。

`bootstrap_database.py` 不加参数也会自动准备自带数据库。原来的 `--source-config` 和 `--mysql-home` 组合仅用于维护时从指定源库只读复制，普通运行无需提供。构建工具 `build_bundled_database.py` 从平台已验证的独立副本生成默认基础包；`build_portable_package.py` 生成不含本机状态的ZIP运行包。后台源码仍由 `bootstrap_agents.py` 构建并在运行时使用 `vendor` 副本。
