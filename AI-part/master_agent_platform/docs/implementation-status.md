## 2026-11-16 字段来源兜底与错配修复

确认原统一编辑器在行来源缺失时回退到当前产品分片PDF、页码缺失时回退到第1页，还会将越界页码夹到文件首尾页。这会使模板默认值、未选中行和无依据数据也能打开文件；项目清单选择其它产品时也可能误用当前产品原文。此外，材料模型抽取曾把所有结果粗略关联到首个文本片段，该关联没有逐条证据。

已移除字段查看器的这些回退。只接受当前产品已登记文件的明确绑定，核对SHA256及有效页码；无法定位时禁用文件依据入口并说明原因。已发生来源复查的行优先采用复查候选记录，人工修改、未保存修改和适用模板默认值只显示形成依据；材料自动补全字段不能沿用同一行材料牌号的PDF作为该值来源。“产品原文（参考）”单独标明用途，项目清单按选中产品定位，未关联产品不回退到其它产品。查看器分别显示记录的文件页和映射的原文页，不擅改页码或高亮框。

条件后台及补充资料解析在实际调用边界为有页码的文档抽取行绑定文件及版本，模板默认值不加PDF绑定。材料后台和界面后台副本改为按模型摘录唯一匹配真实文本片段；无匹配、歧义或空摘录仍保留材料候选，但不生成文件定位。副本清单保留原源码摘要并更新平台补丁后的副本摘要。

验证：119项回归通过，包含17项来源专项；五个真实模块的独立产品编辑、保存及审核回流通过，并检查了选行后的来源状态与对话框。另对两台真实产品重新运行离线条件后台，分别取得24/20条有明确文件页的候选行、25/26条形成依据行，原11台正式产品快照摘要未变。原生嵌入的五模块20个缩放/拉伸场景通过。本轮没有开启桌面屏幕捕捉。回执：`workspace/evidence/source-evidence-regression.log`、`workspace/evidence/unified-ui/verification.json`、`workspace/evidence/source-cases/verification.json`。

边界：旧任务缺失或错误的定位不会因界面更新而自动修复；必须重新抽取、绑定和审核。文件、页码、版本匹配只证明候选位置可追溯，不证明该位置支持本行所有字段，也不代替逐字段工程语义核验。管口及部分管束数据尚未记录字段级文件依据时，入口保持不可用，只允许独立浏览产品原文参考。

## 2026-11-16 Windows 模块嵌入尺寸与 DPI 修复

真实Windows嵌入复现了材料表格塌缩：宿主DPR为2.0、模块为1.0；模块在拥有它的Qt进程内仍是顶层窗口，未随宿主同步尺寸。模块标签数据区仅55像素高。此前独立编辑器及离屏检查没有覆盖这条跨进程显示路径。

数据标签区的最小高度为300逻辑像素，随字号及跨进程DPI比例增加，空间不足时由滚动区承接。材料列宽按内容调整并有上下限。空操作回执默认收起，有回执时自动展开，错误与保存功能保留。
