# 数据中心

入口：主系统菜单 **工具 → 数据中心**。在主窗口内以单个标签页打开，重复点击会回到已有标签页。

代码独立放在 `modules/data_center`。复用用户提供的 DogiCat 0.9.0 数据库核心、查询构造器、字段类型工具，界面使用主系统已有的 PyQt5。压缩包中的个人连接配置和凭据没有导入。原始文件校验值保存在 `vendor/SOURCE.json`。

## 使用方法

1. 左侧统一展示本地 MySQL 的业务数据库。双击表名打开数据；顶部“产品范围”填写产品ID可过滤含产品ID的表，留空表示全部产品。
2. 在表格中选择一个具体单元格，点击“查看字段血缘”。节点定位包含数据库、表、完整主键/唯一定位条件、字段及实际值。
3. 紫色节点表示产品设计活动库的过程数据，蓝色节点表示其他取值依赖库。蓝色实线是已保存的直接取值绑定；橙色虚线是根据现有初始化代码和记录条件识别的历史来源候选。
4. 点击候选连线后点“确认候选连线”，核对影响预览再保存。一个目标字段只有一个直接来源；多个目标可以共用来源，支持多级传递。
5. 任意业务字段均可作为手工建链的起点。在数据表或画布中“记为取值来源”，然后切换到其他库的目标单元格，点击绑定。画布已有两端节点时，可以从来源节点右侧圆点拖线到目标节点。重新绑定会替换原来源，并同步更新后续已绑定字段。
6. 双击节点修改字段值；表格支持拖选、Ctrl / Shift 多选后统一填写。目标已绑定时，可修改上游，或勾选“断开所选字段的现有来源，改为独立值”。空文本和 NULL 分别处理。
7. 所有修改先展示跨库影响预览，确认后统一保存。取消预览不会写入业务数据。“断开来源”保留当前值。拖动节点位置只调整画布布局。
8. “修改记录”展示字段值、链路、操作人和时间，可查看明细并预览撤销最近一次操作。撤销同样会校验外部修改，不会强行覆盖新数据。

SQL 查询台支持单条 SELECT、SHOW、DESCRIBE、EXPLAIN 及跨库查询。表格可导出当前页 CSV，画布可导出 PNG。DDL 展示用于检查表结构，字段写入统一走血缘事务。

## 血缘来源与适用范围

- 浏览覆盖当前连接账号可见的业务库和表，不将同名字段或相等的值自动判为依赖。
- 已内置并核对的初始化取值规则包括产品条件模板、元件材料模板、元件附加参数及合并参数、管口附加参数、布管参数默认表、产品需求到活动表的类型/型式/阶段。布管默认值按产品型式区分 U 型管和其余型式。
- 历史初始化复制不能证明某个现有值仍跟随模板，所以候选关系必须经用户确认才进入联动。未覆盖的业务来源显示“暂无已登记链路”，可以明确指定记录和字段后手工建链。
- 本期联动是直接取值关系。计算公式、DLL 内部运算、图纸和报告重新生成沿用原业务流程；修改输入后需要重新计算/生成。画布不会把未核实的推导过程伪装成完整血缘。
- 在数据中心内更改上游会自动传递到已绑定的下游。其他业务界面、外部 SQL 或外部程序写入后，点击“检查并同步已绑定链路”预览并同步；没有安装数据库触发器或后台写入监听。已打开的业务页面应重新加载后读取新值，避免继续使用页面缓存。
- 当前连接复用 `modules.db_backup.LOCAL_DB_CONFIG`，支持同一 MySQL 服务器中的多个库在同一事务内联动；没有添加跨服务器的分布式提交。

### 产品ID的来源

产品ID有单独的身份来源图。新建、复制或JSON导入时的编号生成代码，需求库的产品主记录、活动库的产品主记录，以及当前子表中的产品ID会一起展示。两张主表可由同一次新建操作写入相同ID，图形不会假定需求表先复制到活动主表。选择主记录的产品ID后，可以展开其他活动子表的实际ID字段，每表最多显示2条并提示其余记录。

这些青色连线表示产品身份传递及归属，均为只读依据；不会把同名字段、相同值直接登记成联动绑定。主记录缺失、同一产品ID不唯一、项目ID不一致或代码尚未解析时，会说明核对边界。代码入口展示当前可用路径，不能证明历史记录实际走过哪个入口。用于记录定位的ID节点没有改绑圆点，数据库仍会校验并拒绝直接修改定位键。

“字段读写依据”也包含WHERE条件中的产品ID，标为“仅定位引用”。例如 `UPDATE ... SET 参数值=%s WHERE 产品ID=%s` 表示用产品ID定位记录，写入的是参数值，不是产品ID。原来产品标准数据表的产品ID没有来源，是因为缺少身份关系且过滤索引漏掉了定位字段。

## 活动库内部流转与界面输入

在 **工具 → 数据中心 → 表流转与界面** 中查看。也可以从数据浏览点击“表与界面流转”，或在字段画布点击“输入与处理依据”，直接定位当前表/字段。

- **流转图**：显示界面输入、活动表读写和业务处理。流程选择器包含条件保存、元件材料投影、布管参数同步、管口分类/载荷标识、布管计算/保存、强度提交/结果回写等9组流程。
- **界面输入清单**：20组控件/文件输入映射，列出业务界面、落库字段、保存触发和映射条件，并标明代码变化后的待复核或停用状态。覆盖条件输入五表、元件/合并/管口/附件参数、管口及附件定义、管口载荷和布管入口。它不是“20个字段”；一组可能对应多列或动态参数行。
- **字段读写依据**：按表、字段、业务界面和关键字筛选SQL位置。选中记录可向上追溯变量赋值、字段键、条件分支、游标查询结果、实参/形参和被调用函数的返回/写入语句；双击进入“语句级来源”图。函数定义行仅作为参数声明边界，不代替内部代码位置。超过500处时提示继续筛选。
- **语句级来源**：节点定位到实际语句的行号并显示相关表达式、条件和SQL。“调用来源”可选择不同调用方，逐一核对具体实参；默认图形突出取值链，勾选“显示定位参数与连接上下文”可展开辅助依据，详情始终保留完整的追溯结果。“函数关联表”保留函数内表读写概览。静态追溯有10层及条数上限，遇到上限、动态分派、未解析入口和DLL均显示边界，不宣称全部运行路径已还原。
- **全部表覆盖**：覆盖数量随重新扫描更新，当前表结构有47张表；没有找到代码读写位置、没有独立界面输入或入口已经移除的情况明确标识。新扫描检查全部业务源码文件，包含没有直接SQL但参与取值的辅助函数。派生值、几何数据和快照不能冒充人工输入。

具体字段画布增加了同产品、同记录范围的腐蚀裕量及管口标识映射，显示数据库当前值；不存在的目标记录会提示，不能凭空创建。固定/浮动管板等元件名称显示在节点中。模板候选同时核对参数含义，排除“参数ID相同、参数名称不同”的伪来源。

**青色点线为只读代码依据，蓝色实线才是已确认的联动绑定。** 界面和处理节点可查看详情，不能拖线写入数据库。条件同步、计算和分类会显示触发条件；计算提交表是同次输入JSON的快照，DLL实际读取JSON，结果另行回写。代码索引不能证明某次产品操作已经执行，也不记录尚未保存的界面输入值。真实字段的直接联动编辑仍经过预览和事务校验。

索引是可重建的静态资源，不导入业务模块、不执行业务函数，也不记录数据库中的产品值或连接口令。控件、函数、赋值、SQL和相关表达式形成可独立读取的语句级证据；连接参数及敏感赋值经过隐藏。

### 刷新与代码更新

点击 **刷新并重新检查**：后台重新读取活动库结构、扫描新增/修改/删除的业务源码、解析函数内部来源，再原子替换索引并更新当前界面的清单和字段画布，无需退出数据中心。进度显示当前文件。数据库暂时不可达时沿用已有表结构继续分析，明确提示“数据库结构未核对”。扫描/写文件失败保留原索引；语法错误的文件单独报告，不混入上次文件的旧依据。扫描期间代码继续变化则拒绝发布不一致结果。

人工核对的字段精确对应与流程标签有独立版本指纹，包含被调用函数。刷新不会自动认可旧规则：入口移除时停用，函数/调用链变化时标为待复核；新SQL和语句级依据仍然可看。开发者核对规则后才能更新 `_reviewed_rules.py`，普通刷新不会改写它。仅移动行号/修改注释不改变规范化AST指纹。解析的是磁盘源码，已加载的业务模块仍需随正常程序升级或重启更新。

开发命令（默认沿用索引里的表结构，不要求数据库运行）：

```powershell
python -m modules.data_center.source_index
python -m modules.data_center.source_index --database
```

命令行重建后，在已开的界面点击刷新加载；使用界面刷新本身则立即生效。“核对代码版本”仍可单独检查变更。当前两个无效脚本 `qiangdujisuan/jiekou_python/bijiao_jiaoben.py`、`TwoD/temp1.py` 有语法错误，列在检查结果中；表覆盖数不代表每条动态SQL及所有历史入口均已解析。

### 安装包没有源码的情况

`donglanpec.spec` 在 `Analysis` 前自动调用 `prepare_bundle()`，从打包时的源码重新生成 `flow_catalog.json.gz` 和 `_build_info.py`；前者是压缩证据资源，后者编译进入程序，绑定资源SHA256、源码构建标识和应用版本。不要绕过spec直接用旧索引打包。旧的 `flow_catalog.json` 仅用于开发环境首次升级时获取表结构，不进入新安装包。

安装版刷新会校验资源与当前编译程序是否匹配、重新载入证据并重新检查可连接的数据库结构，不向安装目录写入，也不需要原始业务 `.py` 文件。可以查看已保存的内部语句和调用来源。它不能在无源码条件下推导另一份新代码；程序升级时由新安装包提供相匹配的新索引。缺少资源、资源损坏、构建或版本不匹配会明确报错，不能静默沿用错误版本。

手动生成发布资源可运行 `python -m modules.data_center.source_index --bundle`，不导入主程序，也不执行主程序网络/登录/计算逻辑。发布前应查看扫描错误和待复核规则。

## 数据一致性与持久化

链路与修改日志保存在本地 MySQL 的 `数据中心配置库`：

| 表 | 用途 |
| --- | --- |
| dc_state | 全局修改版本和并发提交锁 |
| dc_edges | 精确到记录字段的已确认链路 |
| dc_history | 同事务保存的原值、新值、链路前后状态、操作人和时间 |

仅浏览和预览不会创建该库；第一次确认保存时初始化。它已经加入主系统的**可选备份库**列表，不影响旧备份的完整性判断。恢复业务数据时，应同时核对/恢复对应血缘配置，避免把不同时间的业务记录与链路混用。

提交前锁定并复查所有相关字段，检查血缘版本、循环依赖、唯一定位、字段类型、NULL 约束及事务表类型。业务值、链路、版本和历史一并提交，任一失败全部回滚。保存后还会读回字段，检查数据库类型转换、截断、舍入或触发器造成的不一致。

主键和用于定位记录的唯一键不能直接修改。没有数据库主键的参数表，会尝试使用实际唯一的参数名称及上下文定位，并在提交时重新锁定检查；无法唯一定位的记录可浏览，但不能安全地建立写入链路。写入来源和目标要求是 InnoDB 实体表。二进制文件字段可查看，文本编辑器不修改 BLOB。

## 验证与运行

依赖使用项目现有的 Python 3.9+、PyQt5 和 PyMySQL，无需新增图数据库或网页运行环境。

在主系统启动本地 MySQL 后，可单独预览相同的界面：

```powershell
python -m modules.data_center
```

回归测试使用随机命名的 `dc_test_*` / `dc_trace_test_*` 隔离数据库，结束后删除，不修改业务表。包括原有20项数据库事务、4项Qt编辑交互，以及新增的来源解析、跨产品隔离、字段映射、只读节点与界面检索检查：

```powershell
python -m unittest discover -s modules/data_center/tests -p 'test_*.py' -v
```

实际 MainWindow 中的菜单、单实例标签页和现有产品数据浏览/画布也已经运行验证。验证截图见项目 `outputs/data_center/`。

独立数据中心窗口可用 `python tmp/check_data_center_flow_gui.py --standalone` 验证实际数据的只读血缘和界面。整机模式省略该参数，仍遵循主程序的内网服务器检查；内网不通时整机启动验证不可用，不修改该检查。

数据中心代码通过 `main.py` 的显式导入进入现有 PyInstaller 依赖分析。`donglanpec.spec` 自动生成并收录 `modules/data_center/flow_catalog.json.gz`，内部表达式从索引展示，不随资源复制业务源码。

`tmp/check_data_center_refresh_gui.py` 验证真实刷新按钮与语句画布；`tmp/data_center_package_probe.py` 用于构建无源码的验证EXE，检查实际内部取值行、资源版本和刷新行为。完整主系统安装包未在此次功能修改中重建。
