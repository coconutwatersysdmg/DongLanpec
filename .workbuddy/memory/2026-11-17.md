## 修复：打开老产品时管束图形视图很小（点一次布管后正常）

**现象**：选中老产品打开管束，中间圆形预览图很小；再点一次"布管"就变成正常大小。参数表无差异。

**根因**：纯视图缩放时机问题，与布管算法/复现元件无关。`draw_layout()` 末尾 `My_Piping.py:22373` 的 `graphics_view.fitInView(...)` 按调用时刻的 viewport 尺寸算缩放；打开老产品时这条链在 `TubeLayoutEditor.__init__`(:1547) 内同步跑完（`setup_ui`→`load_initial_data`→`initial_operation`→`calculate_piping_layout`→`draw_layout`），此时窗口未 show、viewport 未经布局计算，算出偏小的缩放；`showEvent` 原本只做按钮状态/表格对齐，没有补 fit；`resizeEvent`(:22082) 虽有 fit 但首次显示时不可靠。点布管时界面已显示，同一行 fitInView 算出正常比例。`create_scene`(:22875) 重复 setSceneRect 但不 fit，属隐患（本次未动）。

**方案一已实施（仅改 My_Piping.py 一处，QTimer/Qt 顶部已导入）**：`showEvent`(:3416) 末尾加首次标志 `_initial_view_fit_done`，用 `QTimer.singleShot(0, self._fit_layout_view)` + `singleShot(50, ...)` 双保险补一次自适应缩放；新增 `_fit_layout_view()`(:3431) 调 `fitInView(sceneRect, Qt.KeepAspectRatio)`，带 hasattr/try 保护。只做视图缩放，不动布管数据、不动元件复现。

**验证**：py_compile 通过；pytest 未能运行（默认 python 无 pytest，venv 因 PYTHONHOME/PYTHONPATH 注入 + encodings 缺失无法启动）——待用户在实际软件中打开老产品确认图形大小。

**附带发现**：`resizeEvent`(:22082) 无条件 fitInView 会冲掉用户 Ctrl+滚轮手动缩放，拖窗口即丢失。若以后要保留手动缩放，需加 `_user_zoomed` 标志位跳过自动 fit。本次未改。
